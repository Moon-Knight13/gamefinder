GameFinder

Know when your players are free before you post the game.

Players mark broad availability, the bot shows DMs when enough people are free, and games land in windows that actually work. One bot for the whole scheduling loop.

The scheduling loop

Players mark availability/available — tap Morning / Afternoon / Evening across the week.
▼
Bot aggregates insights/windows — ranked slots, heatmap, response rate. Threshold-filtered.
▼
DM posts a game/game create — picks a viable window, sets player cap and details.
▼
Bot notifies & tracks RSVPs@-mentions available players. Three-tier RSVP: Going / Maybe / Can't.
▼
Game happensReminders, Discord Event, prep summary for the DM.

The problem

Why this exists

Every scheduling bot optimizes for "find one best time for one event." GameFinder optimizes for "show me the landscape so I can make better decisions over time."

🎲

Availability intelligence

Standing data, not one-off polls. DMs see which slots consistently have enough players before committing to a date.

✅

Five-tier RSVP

Going, Maybe, Can't, Spectator, Waitlist. "4 Going, 2 Maybe" is actionable. DMs get the signal they need. Quorum auto-creates a Discord Event.

🌍

Timezone-native

All times stored UTC, displayed in each viewer's local timezone via Discord timestamps. Set once, never think about it again.

🛡

Privacy by design

Minimal data: Discord IDs, timezone, availability blocks. Auto-purged. Delete on request. Guild-isolated queries prevent cross-server leakage.

Architecture

How it's built

Single-process Python bot. No external services. SQLite handles the scale.

Bot internals

GameFinder Bot
Cogs (slash commands)
availability.py, windows.py, games.py, campaigns.py, admin.py — each handles one domain
Utils
time_blocks.py (timezone math), formatting.py (shared helpers, bar charts), scheduler.py (purge, reminders, widget updates)
Database layer
SQLite + WAL mode via aiosqlite. 10 tables, every query scoped by guild_id. Auto-migration on startup

discord.py 2.7+ with Components V2 (LayoutView, Container, Section) for rich interactive UI. APScheduler for reminders, auto-purge, and widget updates. icalendar for .ics import.

Data model

guilds users availability recurring_availability games rsvps campaigns campaign_roster sessions

Every table that holds user data includes guild_id. A query missing guild_id is a security bug. Availability uses a unique constraint on (guild_id, user_id, date, block) for safe concurrent upserts.

Deployment

Oracle Cloud free tier ARM VM Docker Compose GitHub Actions SSH deploy

Bot connects outbound to Discord gateway. No exposed ports, no web server, no reverse proxy. Push to main triggers CI, then auto-deploys on green.

The loop

From idea to game night

Mark

Players tap AM/MID/PM slots on a weekly calendar. Set recurring with one click.

Insight

Bot ranks oneshot windows and identifies campaign-viable weekly slots.

Post

DM hits Post Game — modal pops, game is live in seconds.

Notify

Bot @-mentions players whose availability matches the slot.

RSVP

Going / Maybe / Can't / Spectator / Waitlist — five signals for planning.

Play

Quorum hit — Discord Event created, Going players DM'd the link.
